    Validation not supported for analytics service.

## Unique Aspects

### 1. Read-Only Service Pattern
Unlike CRUD services, AnalyticsService:
- Does not create, update, or delete entities
- Provides read-only aggregation across multiple models
- Validates that it's not used for CRUD operations
- Extends BaseService for infrastructure benefits only

### 2. Multi-Model Queries
Analytics across multiple models:
- **User** model: User count in system analytics
- **Assessment** model: Assessment metrics
- **Response** model: Primary data source
- **Team** model: Team member performance

### 3. Expensive Aggregation Queries
- System analytics loads all responses with eager loading
- Team analytics iterates through all team assessments
- Caching critical for performance (5-minute TTL)

### 4. Integration with Refactored Services
```python
# Uses refactored AssessmentService
assessment = await AssessmentService.get_by_id(db, id=assessment_id)

# Uses refactored ResponseService
responses = await ResponseService.get_by_assessment(db, assessment_id=assessment_id)
```

## Lessons Learned

### 1. Read-Only Services Can Extend BaseService
BaseService isn't just for CRUD - it provides infrastructure benefits:
- Structured logging with EventType
- Error handling patterns
- Caching strategy
- Architectural consistency

### 2. Appropriate Validation for Service Type
For read-only services, validation methods should:
- Raise ValidationException for unsupported operations
- Clearly communicate service contract
- Prevent accidental misuse

### 3. Caching Critical for Aggregation Queries
Analytics aggregation queries are expensive:
- System analytics loads all responses
- Team analytics iterates multiple assessments
- 5-minute cache significantly reduces database load

### 4. Service Integration Matters
AnalyticsService integrates with refactored services:
- Uses AssessmentService (refactored)
- Uses ResponseService (refactored)
- Full migration chain critical

### 5. Singleton Pattern Simplifies Integration
Importing singleton as class name preserves compatibility:
```python
from app.services.analytics_service_refactored import analytics_service as AnalyticsService
# All existing AnalyticsService.method() calls work unchanged
```
