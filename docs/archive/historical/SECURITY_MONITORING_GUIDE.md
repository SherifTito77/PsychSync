## Overview

The Security Monitoring System provides real-time threat detection, automated incident response, and comprehensive audit logging for the PsychSync platform. It helps protect against:

- **Brute force attacks** - Detects repeated failed login attempts
- **Unauthorized access** - Identifies permission escalation attempts
- **Data exfiltration** - Monitors bulk data exports
- **Behavioral anomalies** - Detects automation and suspicious patterns
- **Geographic anomalies** - Identifies impossible travel scenarios

### Key Features

✅ **Real-time Analysis** - Threat detection as events occur
✅ **Automated Response** - Immediate containment actions
✅ **Comprehensive Auditing** - Full compliance trail (SOC 2, HIPAA, GDPR)
✅ **Interactive Dashboard** - Visual security metrics and trends
✅ **Configurable Thresholds** - Tune detection sensitivity
✅ **Safe Automation** - Approval workflows prevent false positives

## Components

### 1. Audit Logger (`app/monitoring/audit_logger.py`)

**Purpose**: Comprehensive audit trail for compliance and security

**Features**:
- 30+ event types (auth, authz, data, config, security, file, system)
- Multiple backends (console, file with rotation, database)
- Automatic alerting for high/critical events
- Query interface for reporting

**Key Classes**:
- `AuditEvent` - Immutable event record
- `AuditLogger` - Main logging interface
- `AuditQuery` - Query builder for reports

**Example Usage**:
```python
from app.monitoring.audit_logger import audit_logger, AuditEventType, AuditSeverity

# Log authentication event
await audit_logger.log_auth_event(
    event_type="login_success",
    severity="info",
    user_id=123,
    ip_address="192.168.1.1",
    success=True
)

# Log security event
await audit_logger.log_security_event(
    event_type="brute_force_detected",
    severity="high",
    user_id=456,
    ip_address="10.0.0.1",
    details={"failed_attempts": 10}
)
```

### 2. Security Analytics (`app/monitoring/security_analytics.py`)

**Purpose**: Real-time threat detection and pattern recognition

**Features**:
- 5 detection rules (brute force, unauthorized access, bulk operations, anomalous patterns, geo anomalies)
- Event history tracking with deques (O(1) memory management)
- Per-user and per-IP event tracking
- Configurable thresholds
- Real-time metrics aggregation

**Key Classes**:
- `RealTimeSecurityAnalyzer` - Main analysis engine
- `SecurityEvent` - Real-time event wrapper
- `ThreatIndicator` - Detected threat with mitigation

**Detection Rules**:

| Rule | Threshold | Severity | Response |
|------|-----------|----------|----------|
| Brute Force (User) | 5 failed in 15 min | HIGH | Lock account, terminate sessions |
| Brute Force (IP) | 5 failed in 15 min | CRITICAL | Block IP |
| Unauthorized Access | 3 denied in 1 hour | HIGH | Alert admin, increase monitoring |
| Bulk Data Export | >100 records | HIGH | Require approval, alert admin |
| Automation | Rapid successive requests | LOW | Rate limit, increase monitoring |

**Example Usage**:
```python
from app.monitoring.security_analytics import security_analyzer, SecurityEvent

# Create security event
event = SecurityEvent(
    event_type="auth.failed",
    timestamp=datetime.utcnow(),
    user_id=123,
    ip_address="192.168.1.1",
    severity="high",
    details={}
)

# Analyze for threats
threats = await security_analyzer.analyze_event(event)

for threat in threats:
    print(f"Threat: {threat.indicator_type}")
    print(f"Severity: {threat.severity}")
    print(f"Description: {threat.description}")
    print(f"Mitigation: {threat.mitigation_suggestions}")
```

### 3. Incident Responder (`app/monitoring/incident_response.py`)

**Purpose**: Automated incident response and containment

**Features**:
- Configurable response actions by threat type
- Confidence thresholds to prevent false positives
- Approval workflows for dangerous actions
- Cooldown periods to prevent response loops
- Manual override capabilities

**Response Actions**:

| Action | Requires Approval | Cooldown |
|--------|-------------------|----------|
| Lock Account | Yes | 30 min |
| Terminate Sessions | Yes | 30 min |
| Block IP | No | 60 min |
| Rate Limit IP | No | 15 min |
| Alert Admin | No | None |
| Alert User | Yes | 60 min |

**Example Usage**:
```python
from app.monitoring.incident_response import incident_responder

# Respond to detected threat
results = await incident_responder.respond_to_threat(
    threat=threat_indicator,
    affected_entities=["user_123", "192.168.1.1"],
    auto_approve=False  # Require approval for account actions
)

for result in results:
    print(f"Action: {result.action}")
    print(f"Result: {result.result}")
    print(f"Target: {result.target}")
```

## Configuration

### Detection Thresholds

Configure threat detection sensitivity in `security_analytics.py`:

```python
self.thresholds = {
    'failed_auth_attempts': 5,  # Brute force threshold
    'failed_auth_window_minutes': 15,
    'bulk_data_export_threshold': 100,
    'unauthorized_access_threshold': 3,
    'suspicious_patterns_enabled': True
}
```

**Tuning Guidelines**:
- **Lower values** = More sensitive, more false positives
- **Higher values** = Less sensitive, may miss threats
- **Recommendation**: Start with defaults, adjust based on false positive rate

### Response Configurations

Configure automated responses in `incident_response.py`:

```python
self.response_configs["brute_force"] = IncidentResponse(
    threat_type="brute_force",
    min_confidence=0.85,  # Only respond if 85%+ confident
    min_severity=ThreatLevel.HIGH,
    actions=[
        ResponseAction.INCREASE_MONITORING,
        ResponseAction.ALERT_ADMIN,
        ResponseAction.TERMINATE_SESSIONS,
    ],
    requires_approval=True,  # Account actions need approval
    cooldown_minutes=30  # Don't repeat action for 30 min
)
```

### Audit Logging Backends

Configure logging backends in `audit_logger.py`:

```python
# Console backend (development)
console_backend = ConsoleBackend()

# File backend (production)
file_backend = FileBackend(
    log_file="/var/log/psychsync/audit.log",
    max_size=100 * 1024 * 1024,  # 100MB
    backup_count=10
)

# Database backend (production)
db_backend = DatabaseBackend(async_session_maker)

# Combine backends
audit_logger = AuditLogger(backends=[console_backend, file_backend, db_backend])
```

### Basic Audit Logging

```python
from app.monitoring.audit_logger import audit_logger

# Log authentication
await audit_logger.log_auth_event(
    event_type="login_success",
    severity="info",
    user_id=user.id,
    ip_address=request.client.host,
    success=True

# Log authorization
await audit_logger.log_authz_event(
    event_type="access_denied",
    severity="high",
    user_id=user.id,
    resource_type="assessment",
    resource_id=assessment_id
)

# Log data access

    event_type="record_accessed",
    severity="info",
    user_id=user.id,
    resource_type="response",
    resource_id=response_id,
    details={"action": "view"}
)
```

### Real-time Threat Detection

```python
from app.monitoring.security_analytics import security_analyzer, SecurityEvent

# Create security event from application event
security_event = SecurityEvent(
    event_type="auth.failed",
    timestamp=datetime.utcnow(),
    user_id=user.id,
    session_id=session_id,
    ip_address=request.client.host,
    severity="high",
    details={
        "username": request.username,
        "reason": "invalid_password"
    }
)

# Analyze for threats
threats = await security_analyzer.analyze_event(security_event)

# Respond to detected threats
from app.monitoring.incident_response import incident_responder

for threat in threats:
    results = await incident_responder.respond_to_threat(
        threat=threat,
        affected_entities=threat.affected_entities,
        auto_approve=False  # Require approval for account actions
    )

    # Log response actions
    for result in results:
        print(f"Executed: {result.action} -> {result.result}")
```

### Querying Audit Logs

```python
from app.monitoring.audit_logger import AuditQuery
from datetime import datetime, timedelta

# Build query
query = (AuditQuery()
         .filter_by_event_type("auth.login")
         .filter_by_severity("high")
         .filter_after_date(datetime.utcnow() - timedelta(hours=24))
         .limit(100))

# Execute query
logs = await query.execute()

for log in logs:
    print(f"{log.timestamp}: {log.event_type} by user {log.user_id}")
```

### Manual Override

```python
from app.monitoring.incident_response import incident_responder
```

## Best Practices

### 1. Event Logging

✅ **DO**:
- Log all authentication attempts (success and failure)
- Log authorization denials
- Log data access (especially PII/PHI)
- Include contextual details (IP, user agent, session)

❌ **DON'T**:
- Log passwords or sensitive data
- Log request bodies with PII
- Use excessive logging that impacts performance

### 2. Threshold Tuning

**Start with defaults**, then adjust based on:

1. **False Positive Rate**:
   - If too many false positives → increase thresholds
   - If missing threats → decrease thresholds

2. **Environment**:
   - **Development**: Lower thresholds (catch everything)
   - **Production**: Higher thresholds (reduce noise)

3. **User Behavior**:
   - **Internal users**: May have different patterns
   - **External users**: Stricter thresholds

### 3. Incident Response

**Safety First**:
1. Always require approval for account actions
2. Use cooldown periods to prevent loops
3. Monitor automated responses for first week
4. Have manual override process ready

**Escalation Path**:
```
Low Confidence (<70%)  → Monitor only
Medium Confidence (70-85%) → Alert + Monitor
High Confidence (85-95%) → Automated response + Alert
Critical Confidence (>95%) → Immediate containment
```

### 4. Audit Log Retention

**Compliance Requirements**:
- **SOC 2**: 7 years minimum
- **HIPAA**: 6 years minimum
- **GDPR**: No specific requirement, but audit trail needed

**Recommendation**: Keep 7 years for full compliance coverage

### 5. Performance Considerations

- **Async Logging**: Always use `await` for audit operations
- **Batch Queries**: Use limits when querying large date ranges
- **Database Indexing**: Ensure `user_id`, `timestamp`, `event_type` are indexed
- **Log Rotation**: Configure file backend to prevent disk space issues

## Troubleshooting

### Issue: Too Many False Positives

**Symptoms**: Legitimate users getting locked out

**Solutions**:
1. Increase `min_confidence` threshold
2. Increase detection thresholds (e.g., `failed_auth_attempts: 5 → 7`)
3. Whitelist trusted IP addresses
4. Reduce cooldown period

### Issue: Missing Threats

**Symptoms**: Attacks not being detected

**Solutions**:
1. Check event logging is working
2. Verify thresholds aren't too high
3. Review detection rules for coverage
4. Enable debug logging for analyzer

### Issue: Dashboard Not Loading

**Symptoms**: 403 Forbidden or blank page

**Solutions**:
1. Verify user has `is_superuser = True`
2. Check API endpoint is registered
3. Verify frontend service configuration
4. Check browser console for errors

### Issue: High Memory Usage

**Symptoms**: Analyzer consuming too much memory

**Solutions**:
1. Reduce deque maxsize (default: 10,000 events)
2. Reduce user/IP history size (default: 1,000)
3. Enable event pruning for old events
4. Use database backend instead of in-memory

### Issue: Automated Response Not Working

**Symptoms**: Threats detected but no response

**Solutions**:
1. Check confidence threshold is met
2. Verify severity threshold is met
3. Check if action is in cooldown
4. Verify action handler is registered
5. Check approval requirement

## Appendix

### Event Types Reference

#### Authentication Events
- `auth.login` - Successful login
- `auth.logout` - User logout
- `auth.failed` - Failed authentication
- `auth.password_reset` - Password reset request
- `auth.mfa_enabled` - MFA enabled
- `auth.mfa_disabled` - MFA disabled

#### Authorization Events
- `authz.access_granted` - Access allowed
- `authz.access_denied` - Access blocked
- `authz.privilege_escalation` - Privilege escalation attempt

#### Data Events
- `data.record_created` - Record created
- `data.record_updated` - Record updated
- `data.record_deleted` - Record deleted
- `data.record_accessed` - Record viewed
- `data.export` - Data exported
- `data.bulk_access` - Bulk data access

#### Security Events
- `security.breach_detected` - Security breach
- `security.malware_detected` - Malware found
- `security.intrusion_attempt` - Intrusion detected
- `security.ddos_attack` - DDoS attack
- `security.vulnerability_exploited` - Vulnerability exploited

### Severity Levels

| Level | Description | Example |
|-------|-------------|---------|
| `info` | Informational | Successful login |
| `low` | Minor issue | Failed login (1-2 times) |
| `medium` | Moderate concern | Failed login (3-4 times) |
| `high` | Significant threat | Brute force attack |
| `critical` | Severe threat | Account compromise |
